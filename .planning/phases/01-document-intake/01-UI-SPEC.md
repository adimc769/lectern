## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge dot offsets, inline padding |
| sm | 8px | Compact element spacing, chip internal padding |
| md | 16px | Default element spacing, form field gaps |
| lg | 24px | Modal body padding (`p-6`), section padding |
| xl | 32px | Reader content max-width gutters, layout gaps |
| 2xl | 48px | Major section breaks, empty-state vertical rhythm |
| 3xl | 64px | Page-level spacing, source-view top offset |

Exceptions: icon-only touch targets use a 44px minimum hit area (close `X` buttons, remove-file buttons, tab icons) — 44 is a multiple of 4; visual size stays `w-4 h-4`/`w-5 h-5` with expanded padding. Source: default (accessibility standard; no upstream value).

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | 400 | 1.5 |
| Label | 12px | 600 | 1.5 |
| Heading | 16px | 600 | 1.2 |
| Display | 20px | 600 | 1.2 |

Notes (all prescriptive):

- Body 14px/400/1.5: dropzone hints, validation messages, library row subtitles, paste-box text. Source: default, matches existing `text-sm`/`text-xs` usage in `IntakeModal.tsx`.
- Label 12px/600/1.5: field labels (`Lecture Title` pattern → `Document Title`), status badges (READY/PROCESSING/FAILED), tab labels, page-count meta. Uppercase with `tracking-wide` for badges only. Source: default, matches existing `text-xs font-semibold` tabs.
- Heading 16px/600/1.2: modal title (`Add Documents`), reader section headings, source-view title. Source: default, matches existing `text-base font-semibold` modal header.
- Display 20px/600/1.2: extracted-text reader document title only. Source: default.
- Reader prose exception: extracted document paragraphs render at 14px/400 with line-height **1.7** (long-form reading legibility; the only permitted deviation from body 1.5). Source: default.
- Exactly 2 weights (400 + 600). No italic, no 700+ in this phase. Source: default.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Process Document |
| Secondary CTA | Browse files (dropzone link text); Cancel (modal footer, dismisses without storing anything) |
| Empty state heading | No documents yet |
| Empty state body | Upload a PDF, DOCX, or TXT file — or paste your notes — to create your first study source. Accepts PDF, DOCX, TXT up to 25 MB. |
| Paste-box placeholder | Paste your notes here… (TXT-equivalent plain text, stored as a TXT source) |
| Title-field label | Document Title (Optional) — placeholder: `e.g. Biology 101: Cell Respiration notes` |
| Formats reminder | Accepts PDF, DOCX, TXT up to 25 MB. Single file per upload. |
| Local-processing note | Processed locally on your device. Zero internet or cloud APIs needed. |
| Error state — wrong type | That file type is not supported. Only PDF, DOCX, and TXT files are accepted — choose a different file. |
| Error state — over limit | File exceeds the 25 MB limit. Split the document or use a smaller file, then try again. |
| Error state — scanned PDF | This PDF has no readable text layer (scanned images). Export or copy the text as TXT and try again. |
| Error state — encrypted | This file is password-protected. Remove the password and try again. |
| Error state — empty | This file contains no readable text. Check the file contents and try again. |
| Error state — processing failed | Extraction failed: {specific cause}. Your file was not stored — try again or use a different file. |
| Progress — extracting | Extracting text… {progressPercent}% |
| Progress — chunking | Preparing study chunks… {progressPercent}% |
| Progress — ready | READY — {pageCount} pages available for study |
| Destructive confirmation | none in this phase: pre-upload discard (remove selected file / clear paste box) needs no confirmation and leaves no library trace (source: D-06). No document delete ships in Phase 1. |

All rejection copy states cause + next action (source: D-05). Validation fires at file-select time, before any upload (source: D-04, D-09). Recovery returns to the picker with the formats reminder (source: D-07).

## Surfaces & Interaction Contracts

Prescriptive layout for the four Phase 1 surfaces. Placement of the upload surface is the agent's discretion (source: CONTEXT.md) — this contract resolves it as a third tab in the existing `IntakeModal`, mirroring the audio flow.

### S1 — Document upload tab (`IntakeModal` extension)

- Add a third tab `Upload Document` (icon `FileText`) beside `Upload File` / `Record Live`, same tab bar pattern: `py-2.5 px-4 text-xs font-semibold` with navy `border-b-2` active underline. Modal title becomes `Add Study Material`; subtitle stays `Transcribed and summarized on your device`.
- Tab body mirrors the audio upload form: optional `Document Title` input, then a dashed dropzone (`border-2 border-dashed rounded-xl p-6`) with `accept=".pdf,.docx,.txt"`. Dropzone hint: `Drop a document here, or browse files`; sub-hint is the formats reminder verbatim.
- Below the dropzone, a paste-text box labeled `Or paste notes`: `textarea` with `min-h-32`, same input styling as title fields, paste-box placeholder verbatim. File selection and paste box are mutually exclusive — selecting a file disables the paste box and vice versa, with Label-style helper text stating which input is active.
- Client-side validation runs synchronously on select/drop/paste-submit, in this order: (1) extension allowlist PDF/DOCX/TXT → wrong-type copy; (2) size > 25 MB → over-limit copy; (3) empty file (0 bytes) or whitespace-only paste → empty copy. Encrypted/scanned detection that requires parsing happens server-side at intake and returns the encrypted/scanned copy before persistence — still no library trace on rejection (source: D-04, D-06).
- Selected-file chip mirrors the audio pattern: `w-8 h-8` teal icon chip + filename + size in MB + `X` remove button (44px hit area). Footer: `Cancel` + `Process Document` (navy bg, `disabled:opacity-40` until exactly one valid input). Submit navigates to the source view (S3) on success (source: D-03).

### S2 — Mixed library rows

- Documents mix into the existing lecture list, one list with type icons (source: D-12). Row layout: type-icon chip (`w-8 h-8 rounded-lg`, teal-tinted for documents) + title (Body) + meta line (Label, muted: `{PDF · 12 pages}` / `{DOCX · 8 sections}` / `{TXT · pasted}`) + status badge right-aligned.
- Status badges: READY (teal), PROCESSING (muted slate + animated `RefreshCw`), FAILED (rose). Badge text is Label 12px/600 uppercase. Processing rows additionally show `{progressPercent}%` via the existing polling pattern (source: D-13). Title + type + badge + pages only — no other metadata (source: D-11).
- Clicking a document row opens the extracted-text reader S4 (source: D-14), never a details-only panel.

### S3 — Source view with live progress

- After upload the user lands on the document source view (source: D-03): title (Heading), status badge, and a progress region mirroring `PipelineProgress` — `role="region" aria-live="polite"`, linear bar (`role="progressbar"` with `aria-valuenow/min/max/valuetext`), stage steps for document extraction: `Reading file → Extracting text → Preparing chunks → Ready`.
- Poll interval 800ms, same `fetchProgress` pattern (source: D-13). On COMPLETED the view swaps to the reader (S4) with the ready copy; on FAILED it shows the processing-failed copy with a `Try again` button returning to the picker (source: D-07).

### S4 — Extracted-text reader

- Full-viewport reader: Display title, Label meta (`{type} · {N} pages · READY`), then extracted prose at 14px/400/1.7. PDF pages render with `Page N` Label dividers; DOCX renders preserved `h1`/`h2` headings (Heading style) with section anchors for `[Doc, section]` citations; TXT renders paragraph breaks with positional section labels.
- Long-text rule: paragraphs wrap, never truncate; headings over 120 chars wrap to two lines max then ellipsis with `title` tooltip. Page/section dividers are sticky on scroll within the reader pane.

### Global interaction rules

- Keyboard: `Escape` closes the modal; dropzone is focusable and activates the file picker on `Enter`/`Space`; tabs are arrow-navigable with `role="tablist"`. Focus-visible ring per `globals.css` on every interactive element.
- Upload is single-file only with no queue UI (source: D-01). No drag-reorder, no bulk actions, no document delete in this phase.
- Contrast: body text `#0F172A` on `#FFFFFF`/`#FBFBF9` and muted `#64748B` on white both clear WCAG AA; badges use 600-weight 12px minimum.

## UI Considerations

Applicable state considerations resolved: 9 covered, 2 backstop, 0 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | document library list | ✅ covered | Zero documents render the documented No documents yet empty state with the formats reminder and an Upload CTA opening the document tab. |
| empty | paste-text box | ✅ covered | Empty paste box shows the placeholder and keeps Process Document disabled until non-whitespace text is present. |
| loading | extraction progress (S3) | ✅ covered | Live region with linear progressbar and stage steps at 800ms poll, mirroring PipelineProgress; swaps to reader on COMPLETED. |
| loading | mixed library rows | ✅ covered | PROCESSING rows show animated badge plus progressPercent via existing polling; layout identical to READY rows. |
| error | file select validation | ✅ covered | Wrong-type, over-limit, and empty inputs are blocked at select time with the documented cause-plus-action copy; no upload fires. |
| error | extraction failure (S3) | ✅ covered | FAILED badge plus the processing-failed copy with Try again returning to the picker; rejected files leave no library trace. |
| populated | mixed library rows | ✅ covered | Typical volume renders title plus type chip plus badge plus page count in one mixed list with documents and lectures interleaved. |
| zero-one-many | mixed library rows | ✅ covered | One row reads singular page copy (1 page); many rows keep identical row rhythm with no section split between lectures and documents. |
| long-text | reader headings | ✅ covered | Headings over 120 chars wrap to two lines then ellipsis with title tooltip; reader prose always wraps at 1.7 line-height. |
| partial | DOCX without Heading styles | 🧪 backstop | Held-out visual UI-state test: DOCX with custom styles falls back to positional section labels with no fabricated headings. |
| overflow | extracted-text reader pane | 🧪 backstop | Held-out visual UI-state test: page and section dividers stay sticky and prose scrolls inside the reader pane with no page-level overflow. |

Empty-state and error-state copy live in `## Copywriting Contract` above; this section covers state coverage and references those rows.
